# Recipe Entry

<!-- Restaurant-repo skill. Ray ids come from
workers/skills/_shared/food-costs-ids.json (keys `rays.recipes`,
`rays.recipe_components`, `rays.ingredients`) — read it, never retype an id. The lyte
keys below are exact; when a lyte is added or renamed on these rays, update the
Base Structure tables here in the same change. Costing arithmetic belongs to
recipe-costing; this skill writes the structure and the first copy of each
line's cost, which the write checker re-does on save. -->

A recipe card says what the cook does; the field needs what the dish is made
of, in units it can cost. The job is to turn the card into lines that each
point at one thing the restaurant buys (or one thing it preps), in that
thing's own unit, so the dish's cost follows from the invoices without anyone
doing arithmetic by hand. Nothing is invented: a line is on the card, an
ingredient is in the field, a cost came from an invoice.

## Before the first call

1. **Check the ids:** `node workers/skills/_shared/food-costs-ids.cjs --check`. Exit 1 → this restaurant is not handed off yet: write nothing, say which ids are missing, stop.
2. **Know who can answer.** Headless (the "Run a skill" job, a lane, a schedule — nobody at the keyboard): every human gate below is **park-and-notify** — write the pending decision as a Task Board row (`rays.task_board`; `title` what is needed, `human_needed` true, `status` "Not started", `priority` "high", `notes` what it blocks and what clears it), stop that line, keep going with everything it does not block, and name each parked row in the report. A person present: ask instead, and park nothing. The full convention: `workers/skills/README.md` §Convention 2.

## Base Structure

Three rays, all in the **Food Costs** prism. Write by lyte **key**, never by label.

```
Recipe (dish or prep)  ──components──▶  Recipe Component  ──▶  Ingredient (unit, last_cost)
                                              │
                                              └──sub_recipe_id──▶  Recipe (is_prep, yield_unit)
```

### Recipe Components — id at `rays.recipe_components`

One row per line of the recipe.

| Key | Label | Type | Fill with |
|---|---|---|---|
| `recipe_id` | Recipe | relation → Recipes | The dish (or prep) this line belongs to |
| `ingredient_id` | Ingredient | relation → Ingredients | The purchased ingredient — **or** `sub_recipe_id`, never both, never neither |
| `sub_recipe_id` | Sub-Recipe | relation → Recipes | A prep recipe (`is_prep` true) used in this dish |
| `quantity` | Quantity | number | How much, in `unit` |
| `unit` | Unit | text | **The source's unit**: the ingredient's `unit`, or the prep recipe's `yield_unit` — exactly, character for character |
| `unit_cost` | Unit Cost | number | Copied: the ingredient's `last_cost`, or the prep's `cost_per_yield_unit` (4 dp) |
| `line_cost` | Line Cost | number | quantity × unit_cost (4 dp) |
| `name` | Component | text | `<Source name> · <quantity> <unit> · $<line_cost, 2 dp>` — e.g. `Baby Arugula · 3 oz · $0.90` |
| `cost_math` | Cost Math | text | The working. Ingredient: `3 oz × $0.3005 per oz (Baby Arugula last cost — US Foods 2023-06-26) = $0.9015`. Prep: `2 fl oz × $0.4011 per fl oz (Garlic Confit prep: $16.0440 batch ÷ 40 fl oz) = $0.8022`. Must end in `= $<line_cost, 4 dp>` |

The cost source in `cost_math` is the vendor and delivery date of the
ingredient's latest Invoice Item; if that can't be read, write `last cost`
alone and say so in the report.

### Recipes — id at `rays.recipes`

The dish already exists (menu-import made it, or the person did). This skill
writes on it only:

| Key | Fill with |
|---|---|
| `components` | relation (many) → Recipe Components. **Append** the new line ids to the list read live — never replace it |

A **prep recipe** the card needs and the field lacks (a house sauce, a dough)
is created as a Recipes row: `name`, `is_prep` `true`, `yield_quantity` and
`yield_unit` from the card (`40` · `fl oz`), no `menu_price`. Its own lines are
entered by this same procedure, **before** the dish that uses it.

### Ingredients — id at `rays.ingredients`

Read only, except a new ingredient the operator confirmed: `name` (kitchen
name, no brand), `category`, `storage`, `unit` (the base unit recipes measure
it in: `oz`, `fl oz` or `each`) — by the invoice-intake rules for those keys.
No `last_cost` — that only ever comes from an invoice.

## Procedure

1. **Read the card.** Text, spreadsheet, photo (say quantities are read from an
   image) or dictation (repeat it back as a list). List every line as written:
   quantity, unit, item, and any prep note ("minced", "toasted").
2. **Read the field live**: the dish's Recipes row and its existing
   components; all Ingredients (`name`, `unit`, `last_cost`, `each_weight`,
   `density`); all prep recipes (`is_prep` true: `name`, `yield_unit`,
   `cost_per_yield_unit`).
3. **Match each line** to one source — an existing ingredient, or a prep
   recipe — by what the kitchen uses, not by spelling ("EVOO" is Olive Oil,
   Extra Virgin). Apply the modifier rule below to decide whether an item is
   its own line or lives inside a prep.
4. **Convert each quantity to the source's unit** (Conversions below). A
   conversion that crosses kinds without `each_weight` / `density` on the
   ingredient **stops that line** — ask for the weight (headless: park it), never guess it.
5. **Sort the lines** into: ready (source exists, unit converts, cost known) ·
   **no cost** (ingredient exists, `last_cost` blank) · **new ingredient**
   (nothing in the field is it) · **blocked** (unit can't convert).
6. **The human gate — show the table before the first write**: card line →
   source → quantity in source unit → unit cost → line cost, with every no-cost,
   new-ingredient and blocked line marked, and every new prep recipe with its
   yield. Write after the person confirms. A new ingredient is created **only**
   on that confirmation. **When no person is present** (a lane, a scheduled
   run): write the ready lines only, and park everything that needs a person as
   **one Task Board row per dish** (`create_entry` on the Task Board ray, id at
   `rays.task_board`): `title` `Recipe entry needs you — <dish>`, `status`
   `Not started`, `human_needed` `true`, `priority` `high`, and in `notes`
   each held line with its quantity, unit and what would clear it ("create
   ingredient Lemons, unit each?", "each_weight for Limes"). Then stop.
7. **Preps first.** Enter any new prep recipe's lines, then run
   **recipe-costing** (trigger `recipe_change`) so the prep has a
   `cost_per_yield_unit` before a dish line points at it.
8. **Write one line, read it back** (`return_row: true`): links, unit, cost
   and `cost_math` as sent. Then the rest, each with `return_row: true`.
9. **Link the lines** — append their ids to the dish's `components`, read back.
10. **Verify** — every check below. Fix, re-run, then report.
11. **Hand off** to **recipe-costing** with trigger `recipe_change`, today as
    `costed_on`, and the dish ids touched. It writes the dish's total, cost per
    portion, food cost % and its Recipe Cost History row (a `baseline` on a
    dish's first costing). Its report goes in yours.

## Rules

These are the field's lessons, held as rules. Each lesson file keeps the story.

**Costed ingredients only** (`mock-recipes-use-costed-ingredients-only`). A
line is written only on an ingredient that exists **with a `last_cost`**.
A line whose ingredient has no cost is **flagged and held** — listed in the
report and the parked task, not written — because a line with an invented or
zero cost breaks the traceable rollup and stops recipe-costing for every
recipe. Say plainly that the dish's food cost reads low until the held lines
land, and that they land the day an invoice costs the ingredient. Never invent
an ingredient, a cost, or a line the card doesn't have; name a dish for what
its lines really make.

**Unit matches the source** (`component-unit-matches-source`). A line's `unit`
is the ingredient's `unit` or the prep's `yield_unit`, exactly. A card in cups
against an ingredient in oz is converted through `density`; a card in pieces
against an ingredient in oz through `each_weight`. Blank → stop that line and
ask. A silent coercion makes every later cost wrong.

**A prep recipe is a sealed modifier unit** (`prep-recipe-sealed-modifier-unit`).
Anything a guest could sensibly say "no" or "on the side" to — tomato, pickled
onion, a sauce, pita, a drizzle — is a **top-level line** of the dish.
Structural ingredients — flour, yeast, leavener, the salt in a dough — live
**inside a prep recipe**. A sauce the guest can drop or swap is a prep recipe
line on the dish, not its raw ingredients inlined: the prep's own name is the
modifier; what's inside it never is.

**One source per line.** Exactly one of `ingredient_id` / `sub_recipe_id`. A
recipe never uses itself. A prep that would contain itself is a loop — stop.

**Supplies aren't ingredients.** Foil, the to-go box, gloves: not lines.

## Conversions

Within a kind, convert and say so in the line's report row:

| Card unit | To | Factor |
|---|---|---|
| lb · g · kg | oz | × 16 · × 0.03527 · × 35.274 |
| tsp · tbsp · cup · pt · qt · gal · mL · L | fl oz | × 1/6 · × 0.5 · × 8 · × 16 · × 32 · × 128 · × 0.033814 · × 33.814 |
| dozen | each | × 12 |

Across kinds — volume ↔ weight needs the ingredient's `density` (oz per fl oz);
count ↔ weight needs `each_weight` (oz per each). Blank → the line is
**blocked**: ask. A "pinch", "to taste" or "a drizzle" has no quantity — ask
for the real amount; if the person says it's negligible, leave it off and say
so.

## Verification

**Before writing**

| # | Check | Pass when |
|---|---|---|
| 1 | Every card line accounted for | ready + no cost + new ingredient + blocked + left off (with reason) = lines on the card |
| 2 | One source each | every ready line has exactly one of ingredient / prep, and that source exists live |
| 3 | Unit = source unit | every ready line's `unit` = its ingredient's `unit` / prep's `yield_unit`; every conversion shown with its factor |
| 4 | Cost known | every ready line's source has a `last_cost` / `cost_per_yield_unit`; every line without one is in the held list |

**After writing**

| # | Check | Pass when |
|---|---|---|
| 5 | Read-back | listing the dish's components returns every written line with the values sent |
| 6 | Line arithmetic | quantity × unit_cost = line_cost on every line, `cost_math` ends in it (the write checker enforces it on save) |
| 7 | Linked | the dish's `components` contains every written line and every line it had before |
| 8 | Hand-off | recipe-costing ran clean: calculator `errors` empty, its re-run plans 0 writes |

Report it as a table, every time — ✓ or ⚠ per check with the numbers, e.g.
`✓ 1 Lines 11/11 · 8 ready · 2 no cost · 1 new ingredient` ·
`⚠ 4 Lemons: no last_cost — held, parked for the next invoice`. A ⚠ is never
silent: say what it blocks and what would clear it.

## Report

The Verification table first, then per dish: lines written (source, quantity,
unit, line cost), lines held and why (no cost · new ingredient · blocked unit),
conversions applied, prep recipes created with their yield, any Task Board row
parked (its title), and the recipe-costing report — the dish's cost per
portion and food cost %, called **partial** while any line is held.
